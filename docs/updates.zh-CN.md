# 版本匹配与更新提示

[English](updates.md) · [码灵 npm 版本列表](https://www.npmjs.com/package/@nath-vikky/dsh-codekin?activeTab=versions)

这项功能从码灵 `0.4.0-rc.1` 起提供。此前的 `0.3.9-rc.1` 不包含更新检测，也不适配 DSH `0.1.7-rc.1`。

## 2026-09-24 适配目标

| DSH 发布线 | DSH | 对应 dsh-web |
| --- | --- | --- |
| npm `latest` | `0.1.5-rc.3` | `@linxin666/dsh-web-all@0.3.24` |
| npm `next` / 新 RC | `0.1.7-rc.1` | `@linxin666/dsh-web-all@0.4.1` |

最新 dsh-web `0.4.1` 声明要求 DSH `>=0.1.7-rc.1`，不能直接与 `0.1.5-rc.3` 配对。这是两个发布通道，不应只比较包名后面的 `latest` 标签。上表是检查当日的版本快照；实际更新提示会实时按用户正在运行的 DSH 筛选。

`0.4.0-rc.1` 兼容范围为 `>=0.1.5-rc.1 <0.1.6-0 || >=0.1.7-rc.1 <0.1.8-0`。不包含 `0.1.7-alpha`、未经验证的 `0.1.6` 或下一条 `0.1.8` 预发布线。

## 0.4.1 起的兼容声明

上面那串 `0.1.5-rc.1 <0.1.6-0 || 0.1.7-rc.1 <0.1.8-0` 逐版本白名单会被 DSH `0.2.1-alpha.1`
的安装闸门拒绝：闸门拿宿主版本去比对 `peerDependencies` 里声明的区间，而白名单没有任何一支
覆盖 `0.2.0-rc.x` 或 `0.2.1-alpha.x`。

因此码灵 `0.4.1` 改为：

- `engines.dsh` 与 `dsh.compatibility.dsh` = `>=0.1.5-rc.1`（用一条开区间取代逐版本白名单）；
- `dsh.compatibility.dshReleases` 从 `0.1.5-rc.1` 一直列到 `0.2.1-alpha.1` 全部标为
  `compatible`，`0.2.0-rc.x` 线与 `0.2.1-alpha.x` 线都被显式声明；
- `peerDependencies` 里的 DSH 条目一律写成 `*`。

2026-10-04 已在两代核心上验证：DSH `0.2.1-alpha.1` 与 DSH `0.2.0-rc.2` 都能安装（无
`incompatible` 拒绝），并且都成功挂载了码灵的客户端 bundle。

来源：[DSH 发布记录](https://github.com/deepseek-ai/deepseek-harness/releases)、[dsh-web 0.4.1 桌面宿主固定版本](https://github.com/zhu1090093659/dsh-web/blob/v0.4.1/desktop/runtime/host/package.json)、两者的 npm 发布元数据。

## 使用方式

1. 打开码灵后，插件会自动检查兼容的公开版本。
2. 有适配更新时，标题栏的“设置”旁显示“有更新”。点击即可查看当前 DSH、已安装码灵和最新兼容版本。
3. “设置 → 更新”可以手动检查，随时查看检测结果和安装入口。
4. 选择“查看适配版本”打开对应版本的 npm 页面；在 DSH 插件管理中使用弹窗给出的完整包名和版本进行安装。完成后重新打开码灵。

功能只提示，不会执行安装命令、修改 DSH、变更插件配置或更新存档。检查仅请求固定 npm 官方地址的公开码灵元数据，不发送用户版本参数、存档、提示词、对话、路径或令牌。

## 推荐依据

- 从当前 DSH 进程的 CLI 解析实际 `dsh-app-boot` 版本；不使用项目 `package.json`、Codekin 开发 SDK 或环境中的 npm 项目版本冒充宿主版本。
- 同时匹配每个码灵发布包的 `dsh.engines.dsh` 与所有 DSH SDK `peerDependencies`，采用 DSH 相同的预发布版本参与规则。
- 对历史 `0.2.0-rc.5` / `0.2.0` 包额外限定到实际验证的 DSH `0.1.0-rc.5`。它们发布时的 `^0.1.0` 范围过宽，不能作为兼容新版宿主的依据。
- 在匹配结果中选择语义版本最高的正式版或 RC，跳过已弃用发布。只有已经安装同一实验通道的用户，才会看到该通道的实验版本。
- 不盲目推荐 npm 的 `latest`；若已安装版本不兼容，可提供适配的旧版下载入口，但不会自动降级。
- 无法确定 DSH 版本、没有已发布的适配包、网络不可用是三个不同状态，均不会伪装为“已是最新”。当前开发版可能已兼容新 DSH，而 npm 尚未发布对应版本。
- 元数据在 Host 中缓存 6 小时；网络失败退避 15 分钟，手动检查最短间隔 1 分钟。所有窗口共享一次请求，请求有 8 秒超时和 4 MiB 响应上限，插件卸载会中止请求。

## 无法打开码灵时

如果码灵入口已加载，但 Host 游戏服务报错、响应格式不匹配或游戏界面渲染失败，会展示启动帮助，提供版本检查和下载入口。能够确认版本不兼容时，直接显示兼容性提示。普通断网或短暂重启会保留重连与手动帮助入口，不把网络故障判定为版本不兼容。

**宿主完全拒绝加载插件时，插件自身无法显示弹窗。** DSH `0.1.7-rc.1` 会在执行插件代码前核对 SDK peers；浏览器脚本被拦截或插件被禁用也属于这个边界。此时请打开 DSH 的插件管理页，查看码灵的版本兼容诊断，再到 [npm 版本列表](https://www.npmjs.com/package/@nath-vikky/dsh-codekin?activeTab=versions) 或 [GitHub 发布页](https://github.com/Nath-Vikky/dsh-codekin/releases) 获取适配包。无需授予版本豁免或删除存档。

本功能没有修改 DSH 的加载器，也不会绕过它的版本检查。要对“整个插件根本未执行”提供自动弹窗，需要由 DSH 或 dsh-web 的插件管理器提供宿主级入口。
